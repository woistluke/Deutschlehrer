## 2026-07-10 — implemented (all 6 approved same-day, commit 3d2e4a7)

1. **Fix: Conversation tab loses chat history on "Back to chat."** In `js/pages/conversation.js`, `renderChat()` unconditionally creates a brand-new `createRichChat()` instance (and re-sends an opening greeting) every time the chat screen re-mounts — including when returning from flashcards or the session-review screen. Checking your vocab flashcards mid-conversation currently wipes the whole conversation instead of resuming it. Only the "change topic" path should reset; the flashcards round-trip should preserve the existing chat instance/history. Effort: small-medium. Files: `js/pages/conversation.js`.

2. **Reliability: no timeout on AI calls.** `js/ai.js`'s `chatCompletion`/`speak`/`transcribe` have no request timeout, so a hung Groq/OpenAI request leaves the UI stuck on "Denke nach…" / "Checking…" / "Grading…" indefinitely with no recovery besides a full reload. Add an `AbortController`-based timeout (~20-30s) with a clear, retryable error. Effort: small-medium. Files: `js/ai.js`.

3. **Consistency: sentence-drill phase skips forward on failure instead of offering retry.** In `js/pages/runner.js`, `mountSentencePhase()`'s catch block only offers "Skip to conversation," silently dropping the whole sentence-practice phase on a transient network error — whereas the quiz phase (`mountQuizPhase`) offers a proper "Try again" retry for the same class of failure. Mirror the quiz phase's retry pattern here. Effort: small. Files: `js/pages/runner.js`.

4. **Cleanup: stray backup file committed to the repo.** `js/seed.js.bak` is a leftover, superseded backup of `js/seed.js` (confirmed via diff — older/incomplete vocab) sitting in version control with no functional purpose. Remove it. Effort: trivial. Files: `js/seed.js.bak` (delete).

5. **Docs: README's "Integrating with your existing repo" section is stale.** It describes migrating from an original single-file app (legacy `localStorage` keys like `groq_key`/`openai_key`, a "v1.2 folder" not yet promoted to repo root) that no longer exists in this repo — there's no legacy file left to migrate from, and the modular app already *is* the repo root. Either remove this section or mark it as historical/completed so it doesn't send future-you looking for a migration that already happened. Effort: trivial. Files: `README.md`.

6. **Data hygiene: deleting vocab/units leaves orphaned progress rows.** Neither `store.js`'s `deleteVocab`/`deleteUnit` nor the schema clean up matching `progress` rows (progress references `item_id` as free text, not a FK to `vocab_id`, so there's no cascade). Harmless today but accumulates dead rows over time as the curriculum gets edited. Low priority — worth a small cleanup pass either in `deleteVocab`/`deleteUnit` (app-side) or as a periodic Supabase cleanup query. Effort: small. Files: `js/store.js`, `schema.sql`.

## 2026-07-10 (second pass) — implemented (commit e97292d)

Deeper follow-up review at Luke's request, after the first six items above were implemented. Covers ground not fully explored in the first pass: CSS, seed vocab content, and edge cases in the editor/grading flows.

1. **Bug risk: no double-submit guard on quiz/sentence grading.** `gradeAnswer`/`gradeSentence` in `js/pages/runner.js` don't disable the input/Check button while a grading call is in flight (the chat UI already does this via `setBusy()` in `chatui.js` — this doesn't). A double-click, or hitting Enter then clicking Check, can fire two concurrent `quizCall`s for the same question, each calling `recordResult` → `applyAnswer` — inflating `times_seen`/`times_correct` and potentially advancing (or dropping) the SRS ladder twice for one answer. Fix: disable input + button for the duration of the grading call, mirroring `chatui.js`'s pattern. Effort: small. Files: `js/pages/runner.js`.

2. **Bug risk: a unit with zero vocab can permanently softlock all curriculum progress.** `maybePromote()` returns `false` whenever a unit's vocab list is empty, so such a unit can never be marked complete — and `getActiveUnit()` always returns the first non-complete unit in course order, so every unit after it would be permanently unreachable as "up next." This doesn't happen in the current seed data (all 40 units have 14-21 vocab items), but the Curriculum editor's "+ Unit" button happily creates a title-only unit with no vocab yet — a natural "stub now, fill in later" workflow that would trigger exactly this softlock if that stub becomes the active unit before vocab is added. Fix: treat a vocab-less unit as trivially complete (nothing to master) in `maybePromote`/`getActiveUnit`, or warn in the editor. Effort: small. Files: `js/store.js` or `js/pages/runner.js` (`maybePromote`), `js/pages/editor.js`.

3. **Bug risk: unit mastery threshold isn't validated in the Curriculum editor.** The threshold field is `<input type="number" min="0" max="1">`, but `min`/`max` are only soft hints — typing "8" instead of "0.8" (an easy slip) saves verbatim via `parseFloat()` with no clamping. Since `mastery_score` maxes out at 1.0, a threshold above 1 makes that unit's completion mathematically unreachable forever, with no warning telling you why it never clears. Fix: clamp to `[0,1]` on save, or reject/flag out-of-range values inline. Effort: small. Files: `js/pages/editor.js`.

4. **Content quality: ~22 vocab terms duplicated verbatim across different units in the seed curriculum** (44 of 638 rows — e.g. "Ich bin", "die Wohnung", "die Fahrkarte", "Ich möchte", "die Familie" each appear in two separate units, confirmed via a text scan). Each duplicate is a separate, untracked-together vocab row, so mastering a word in an earlier unit doesn't carry over — it gets redrilled from scratch when its duplicate resurfaces later, quietly eating into the ~5-word session slice with something you already know. Also a minor risk for `resolveVocabByLabel`'s substring-matching heuristic when two identical terms exist. Fix: dedupe — keep the earlier (lower-level) occurrence, remove or replace the later one with a genuinely new word. Effort: small. Files: `js/seed.js`.

5. **UX clarity: "review mode" silently runs the full unit vocabulary, not the ~5-word slice a regular lesson uses.** `startSession()` only slices vocab down to `SESSION_SIZE` when `mode === 'curriculum'`; picking a unit in "Review mode" from the Today tab pulls its entire vocab list (14-21 items in the current curriculum) straight into the vocabulary-matching phase — well past the app's own "~5 minute lesson" design target, with no heads-up on the review picker that this is a bigger scope than a normal lesson. Fix: either slice review-mode vocab the same way, or add a short caption near the review picker noting it runs the full unit. Effort: small. Files: `js/pages/runner.js`.

6. **Luke-requested: some vocab words were combined into a single line item (e.g. "eins, zwei, drei", "heute / morgen / gestern") — split each into its own entry, and clean up existing Supabase/localStorage history to match.** Found 24 such combined entries across the seed curriculum (comma- or slash-joined lists of genuinely separate words/forms — distinguished from single phrases that merely contain a comma, like "ich denke, dass" or "Klar, gerne!", which were left alone) and split them into 54 individual rows in `js/seed.js`. Added `splitCombinedVocab()`/`splitCombinedVocabForAllUsers()` to `js/store.js` — a migration (wired into a new Settings admin card) that finds any existing account's vocab rows still holding the old combined text, creates the split rows, evenly divides `times_seen`/`times_correct` across them, copies `srs_level`/`mastery_score`/schedule as-is to each (nothing to subdivide there), and deletes the old row. Also, while auditing for combined items, found and fixed 25 separate exact-duplicate vocab terms scattered across unrelated units (e.g. "die Familie" in two different units as untracked-together rows) — deduped in `seed.js`, keeping the better-fitting occurrence (e.g. "gegessen" now lives only in the irregular-verb unit, correcting a minor mis-categorization). Effort: medium. Files: `js/seed.js`, `js/store.js`, `js/pages/settings.js`.

**Follow-up (same day, commit 23fff84):** Luke asked for the item-4 duplicate fix to also apply to his existing account's live data, not just `seed.js`, and offered Supabase credentials. The sandbox this runs in only has network access to `github.com` (verified: it can't resolve or reach `supabase.co` at all — not a permissions issue, an infrastructure allowlist), so direct database access wasn't possible even with valid credentials. Built the same kind of migration used for item 6 instead: `mergeDuplicateVocab()`/`mergeDuplicateVocabForAllUsers()` in `js/store.js`, wired into a new Settings admin card, for Luke to run himself from his browser (which has normal internet access). Merges each duplicate group into one row — summing review counts, taking the best mastery/schedule state, unioning known errors — using the same keep/remove decisions as the seed.js dedupe, falling back to "keep the oldest row" for any duplicate not in that known list (e.g. one added manually). Safe to re-run.
